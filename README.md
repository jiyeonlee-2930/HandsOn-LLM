### 이 과목의 원칙

교재는 수식 없이 그림으로 설명하는 책이라 초급 과정에 적합합니다. 다만 후반부(10~12장)는 학습 코드가 무거우므로 다음 원칙을 둡니다.

**1. 수식은 다루지 않습니다.** 어텐션도 행렬 연산이 아니라 "어떤 단어가 어떤 단어를 얼마나 참고하는가"의 그림으로 설명합니다.

**2. 백지 코딩을 시키지 않습니다.** 모든 실습은 완성된 노트북에서 1~3줄을 바꾸는 "빈칸 채우기" 형태로 제공합니다. 학생이 작성하는 코드는 매주 5줄 이내입니다.

**3. 장마다 깊이를 다르게 갑니다.**
- **A단계 (직접 실습)**: 코드를 수정하고 결과를 만들어냄 — 1, 2, 4, 5, 6, 8장
- **B단계 (실행·관찰)**: 주어진 코드를 실행하고 결과를 해석함 — 3, 7, 9장
- **C단계 (데모 관람)**: 교수자 시연을 보고 개념과 용도만 이해함 — 10, 11, 12장

**4. 결과가 먼저, 원리가 나중입니다.** 3주차에 이미 프롬프트로 무언가를 만들어 봅니다. 트랜스포머 내부는 6주차에 다룹니다.

## 2. 학습 목표

수강 후 학생은 다음을 할 수 있습니다.

1. LLM이 어떤 종류의 문제에 쓸 수 있는 도구인지 예를 들어 설명한다.
2. 프롬프트를 목적에 맞게 설계하고, 결과가 나쁠 때 무엇을 고칠지 판단한다.
3. 토큰·임베딩·트랜스포머의 동작을 **그림 수준에서** 설명한다.
4. 사전학습 모델로 텍스트 분류와 클러스터링을 실행하고 결과를 해석한다.
5. 자신의 문서로 RAG 챗봇을 만들고, 왜 틀린 답이 나오는지 진단한다.
6. 미세 튜닝이 무엇이고 언제 필요한지 설명한다. (직접 학습은 요구하지 않음)

### 주차별 상세

#### 1주차 — 오리엔테이션 + LLM이란 무엇인가 (1장)

- **오늘 만들 것**: Colab에서 소형 LLM을 불러와 문장 하나 생성시키기
- **개념**: 규칙 기반 → 통계 기반 → 딥러닝 → LLM으로 이어진 흐름, 표현 모델과 생성 모델의 차이, "사전학습된 모델을 가져다 쓴다"는 개념
- **실습**: 노트북 실행 버튼 누르기부터 시작. 프롬프트 문장만 바꿔 보기
- **작성할 코드**: 문자열 1줄
- **활용 도해**: 언어 AI 연대표, 표현 모델 vs 생성 모델 비교도
- **과제**: Colab 실행 화면 캡처 제출 + 관심 있는 LLM 활용 사례 3줄 서술

#### 2주차 — 실습 준비 주간 (Colab·파이썬·허깅페이스)

교재 진도를 나가지 않는 주간입니다. 이후 12주를 위한 투자입니다.

- **Colab**: 셀 실행 순서, 런타임 재시작, GPU 켜기, 세션 끊김 대처, 파일 업로드
- **파이썬 되짚기**: 리스트/딕셔너리, for문, 함수 호출과 인자, 라이브러리 import, 에러 메시지 읽는 법
- **판다스 최소한만**: `read_csv`, `head`, 열 선택, `value_counts` — 이 4개면 학기 내내 충분합니다
- **허깅페이스**: 계정 생성, 액세스 토큰 발급, `pipeline()` 한 줄로 모델 쓰기
- **에러 대응 훈련**: 흔한 에러 5종(모듈 없음, 토큰 없음, OOM, 런타임 끊김, 오타)을 일부러 만들어 보고 고치기
- **과제**: 자기 텍스트 파일을 Colab에 올려 `pipeline()`으로 감성 분석 돌려보기

#### 3주차 — 프롬프트 엔지니어링 (1): 기본기 (6장 전반)

- **오늘 만들 것**: 같은 질문에 대해 나쁜 프롬프트와 좋은 프롬프트의 답을 나란히 비교하기
- **개념**: 프롬프트의 구성 요소(역할·지시·맥락·형식·예시), 지시 튜닝된 모델의 성격, 제로샷과 퓨샷
- **실습**: 요약, 분류, 재작성 세 과제에 대해 프롬프트를 3회씩 개선
- **작성할 코드**: 프롬프트 문자열만
- **활용 도해**: 프롬프트 구성 요소 분해도, 퓨샷 예시 배치도
- **과제**: 프롬프트 개선 일지 (초안 → 3차 개선, 각 단계에서 무엇을 왜 바꿨는지)

#### 4주차 — 프롬프트 엔지니어링 (2): 사고 사슬과 구조화 출력 (6장 후반)

- **오늘 만들 것**: LLM 출력을 JSON으로 받아 표로 정리하기
- **개념**: 사고 사슬(단계별로 생각하게 시키기), 자기 일관성, 출력 형식 강제, temperature가 하는 일
- **실습**: 추론 문제에 CoT 적용 전후 정답률 비교, JSON 출력 파싱해서 판다스 표로 만들기
- **활용 도해**: CoT 흐름도, 프롬프트 기법 계층도
- **과제**: 리뷰 10건을 JSON(점수·요약·키워드)으로 구조화하는 프롬프트 작성

#### 5주차 — 토큰과 임베딩 (2장)

- **오늘 만들 것**: 한국어 문장이 모델별로 몇 개 토큰으로 쪼개지는지 비교표 만들기
- **개념**: 모델은 글자가 아니라 토큰을 본다, 토크나이저 종류에 따른 차이, 임베딩 = 의미를 숫자 벡터로, 유사도 계산
- **실습**: 토크나이저 3종 비교, 단어 임베딩 유사도 순위 확인, 2차원 시각화 관찰
- **활용 도해**: 토큰화 흐름도, 임베딩 공간 시각화
- **과제**: 한국어 문장 5개에 대한 토크나이저 비교 (토큰 수와 쪼개진 모양)
- **초급 유의**: word2vec 학습 과정은 개념만. 대조 학습 수식은 다루지 않습니다.

#### 6주차 — 트랜스포머 안을 들여다보기 (3장) · **깊이 B**

이 과목에서 가장 어려운 주차입니다. 목표는 "구현할 수 있다"가 아니라 **"그림을 보고 설명할 수 있다"**입니다.

- **개념**: 한 번에 토큰 하나씩 생성한다, 어텐션은 "어떤 단어를 얼마나 참고할지 정하는 것", 여러 층을 거치며 표현이 정교해진다, 생성 옵션(temperature, top-p)이 결과를 어떻게 바꾸는가
- **다루지 않는 것**: 쿼리·키·값 행렬 연산, 위치 인코딩 수식, KV 캐시 구현, MoE 라우팅 (용어만 소개)
- **실습**: 어텐션 가중치 히트맵 관찰(코드는 제공), 생성 파라미터 슬라이더 조작
- **활용 도해**: 트랜스포머 블록 분해도, 어텐션 시각화, 토큰 순차 생성도
- **과제**: 어텐션 히트맵을 보고 "이 문장에서 대명사가 무엇을 가리키는지 모델이 알아냈는가" 서술 (코드 없음)

#### 7주차 — 텍스트 분류 (4장)

- **오늘 만들 것**: 한국어 영화 리뷰 감성 분류기 3종을 만들어 정확도 비교
- **개념**: 같은 문제를 푸는 세 가지 방법 — ① 미리 학습된 분류 모델 ② 임베딩 + 간단한 분류기 ③ LLM에게 프롬프트로 시키기. 각각의 장단점과 비용
- **실습**: NSMC 데이터로 세 방법 비교, 정확도 표 작성
- **개념**: 정확도·정밀도·재현율을 표 하나로 이해하기
- **활용 도해**: 분류 파이프라인 비교도, 제로샷 분류 개념도
- **과제**: 세 방법의 정확도·속도·비용 비교표 + 어떤 상황에 무엇을 쓸지 판단

#### 8주차 — 보강주

- 1~4장 및 6장 핵심 개념 정리, 오픈 질의응답
- 실습 미완료분 따라잡기 세션 (조교 상주)
- **팀 프로젝트 주제 확정**: 3인 1팀, "내가 가진 문서로 무엇을 하고 싶은가" 한 장 분량 제안서
- 중간 점검 과제 제출

#### 9주차 — 텍스트 클러스터링과 토픽 모델링 (5장)

- **오늘 만들 것**: 문서 뭉치를 자동으로 그룹핑하고 각 그룹에 이름 붙이기
- **개념**: 정답 라벨 없이 묶는다는 것, 임베딩 → 차원 축소 → 군집화의 3단계, 각 묶음을 대표하는 단어 뽑기
- **실습**: BERTopic으로 뉴스/리뷰 데이터 토픽 추출, 결과 시각화 관찰
- **다루지 않는 것**: UMAP·HDBSCAN 알고리즘 내부, c-TF-IDF 수식
- **활용 도해**: 3단계 파이프라인도, BERTopic 모듈 구성도
- **과제**: 토픽 결과를 보고 "이 묶음은 무엇에 관한 것인가" 사람 손으로 이름 붙이고 타당성 평가

#### 10주차 — 시맨틱 검색 (8장 전반)

- **오늘 만들 것**: 키워드가 하나도 겹치지 않는데도 찾아내는 검색기
- **개념**: 키워드 검색의 한계, 임베딩으로 "의미가 비슷한 것"을 찾는다, 문서를 조각내는 이유(청킹), 벡터 저장소
- **실습**: 문서 임베딩 → 인덱싱 → 질의. 키워드 검색과 결과 나란히 비교
- **활용 도해**: 밀집 검색 구조도, 청킹 전략 비교도
- **과제**: 자기 관심 분야 문서 20~30건을 준비해 검색 인덱스 만들기 (프로젝트 준비 겸용)

#### 11주차 — RAG 챗봇 만들기 (8장 후반)

- **오늘 만들 것**: 자기 문서에 근거해서 답하는 챗봇
- **개념**: 검색 결과를 프롬프트에 넣어주면 환각이 줄어든다, RAG 전체 흐름, 근거 표시, 왜 여전히 틀리는가(검색 실패 vs 생성 실패)
- **실습**: 10주차 인덱스에 생성 단계 연결, 일부러 틀린 답을 유도해서 원인 진단
- **활용 도해**: RAG 전체 파이프라인도, 리랭커 위치도
- **과제**: 자기 RAG 챗봇의 실패 사례 3건 + 원인 분석
- **비고**: 이 주차 결과물이 팀 프로젝트의 뼈대가 됩니다.

#### 12주차 — LLM에 도구 붙이기 (7장) · **깊이 B**

- **오늘 볼 것**: LLM이 스스로 계산기와 검색을 호출하는 과정
- **개념**: LLM은 계산과 최신 정보에 약하다, 도구 호출이란, 대화 기억(메모리), 에이전트가 생각하고 행동하는 순환
- **실습**: 제공된 에이전트 노트북 실행, 도구 하나 추가해 보기
- **다루지 않는 것**: LangChain 전체 API, 커스텀 체인 설계
- **활용 도해**: 메모리 유형 비교도, ReAct 순환 흐름도
- **과제**: 에이전트 실행 로그를 읽고 "몇 번째 단계에서 무엇을 판단했는지" 해설

#### 13주차 — 멀티모달 LLM + 임베딩 모델 만들기 개관 (9·10장) · **깊이 B / C**

- **9장 (B)**: 이미지와 텍스트를 같은 공간에 놓는다는 아이디어, CLIP으로 이미지 검색·제로샷 분류 실습
- **10장 (C)**: 임베딩 모델을 직접 학습시킬 수 있다는 것, "비슷한 건 가깝게, 다른 건 멀게" 학습한다는 직관, 학습 전후 성능 차이 데모 관람
- **다루지 않는 것**: ViT 구조 상세, Q-Former, 손실 함수 종류, MTEB 벤치마크 세부
- **활용 도해**: CLIP 대조 학습 개념도, 임베딩 공간 정렬 그림
- **과제**: CLIP 이미지 검색 데모 실행 결과 제출 (10장 과제 없음)

#### 14주차 — 미세 튜닝이란 무엇인가 (11·12장) · **깊이 C**

직접 학습을 시키지 않습니다. **언제 필요한 기술인지 판단할 수 있게** 하는 것이 목표입니다.

- **개념**: 프롬프트로 안 되면 미세 튜닝, 사전학습 → 지시 튜닝 → 선호 튜닝의 3단계, LoRA는 "모델 전체가 아니라 작은 부품만 바꾸는 것", 양자화는 "정밀도를 낮춰 메모리를 아끼는 것"
- **판단 기준 토론**: 프롬프트 / RAG / 미세 튜닝 중 무엇을 언제 쓰는가
- **데모**: 교수자가 QLoRA 미세 튜닝 전후 출력을 시연, 학생은 결과만 비교
- **활용 도해**: 3단계 학습 파이프라인도, LoRA 저랭크 분해도, 양자화 비교도
- **과제**: 자기 프로젝트에 미세 튜닝이 필요한가 — 필요/불필요 판단과 근거 (코드 없음)

#### 15주차 — 보강주 (프로젝트 발표)

- 팀당 10분 발표 + 3분 질의
- **필수 포함**: 데모 시연, 잘 안 된 사례 최소 1건과 그 원인
- 완성도보다 "무엇을 시도했고 무엇을 배웠는가"를 평가합니다

#### 16주차 — 기말고사

- 개념 이해 중심 (그림 보고 설명하기, 상황에 맞는 기법 고르기)
- 코드 작성 문항 없음. 코드 읽고 결과 예측하는 문항 소수 포함

## 5. 평가 방법

초급 과정이므로 시험 비중을 낮추고 꾸준한 실습 완료에 무게를 뒀습니다.

| 항목 | 비중 | 설명 |
|---|---|---|
| 주차별 실습 과제 | 40% | 12회, 최저 2회 제외. 완료 여부 중심 채점 |

| 출석·참여 | 5% | |

### 채점 원칙
- 실습 과제는 **정답 여부가 아니라 실행하고 관찰한 흔적**으로 채점합니다. 결과가 나빠도 왜 그런지 서술하면 만점입니다.
- 오류 로그를 첨부하고 무엇을 시도했는지 쓰면 부분 점수를 줍니다.

### 팀 프로젝트
- 3인 1팀, 8주차 주제 확정 → 15주차 발표
- **최소 요구사항은 하나**: 자기 팀이 고른 문서로 RAG 챗봇 하나를 동작시킬 것 (11주차 결과물의 확장)
- 여력이 있는 팀은 분류·클러스터링·에이전트를 추가로 결합 (가산점)
- 산출물: 실행 가능한 Colab 노트북 + 발표 슬라이드 + 3쪽 이내 보고서

## 6. 초급 과정 운영 지침

**노트북은 반드시 사전 검증하세요.** LLM 생태계는 라이브러리 변화가 빨라 학기 시작 전 12개 노트북을 전부 재실행해 보고, `requirements.txt`로 버전을 고정해야 합니다. 초급자는 자기 실수와 라이브러리 문제를 구분하지 못해 좌절이 큽니다.

**조교 배치를 권장합니다.** 실습 차시에 조교 1명만 있어도 이탈률이 크게 줄어듭니다. 최소한 8주차 보강주에는 배치하세요.

**API 비용이 드는 실습은 대안을 준비하세요.** 오픈 웨이트 소형 모델(Phi, Qwen, Gemma 등)로 대체 가능한 경로를 함께 제공하면 학생 부담이 사라집니다.

**한국어 데이터를 우선 쓰세요.** 교재 예제는 영어 중심입니다. NSMC(영화 리뷰), KLUE, KorQuAD로 바꿔 실습하면 결과를 직관적으로 읽을 수 있어 초급자에게 특히 효과적입니다.

**페어 실습을 권장합니다.** 2인 1조로 한 화면을 보며 진행하면 막힌 학생이 조용히 포기하는 상황을 줄일 수 있습니다.

**매주 첫 10분은 지난주 복습 퀴즈.** 그림 한 장 띄우고 설명하게 하는 구술 퀴즈면 충분합니다.

## 7. 조정 옵션

- **더 여유롭게**: 12~13주차(7·9·10장)를 통째로 빼고 8장 RAG에 3주를 배정하면 훨씬 편안합니다. 초급 과정에서는 RAG 하나를 확실히 하는 편이 얕게 여러 개 훑는 것보다 낫습니다.
- **더 깊게**: 파이썬 수준이 예상보다 높으면 2주차를 축약하고 3장을 2주로 늘리세요.
- **중간고사 실시**: 8주차를 시험으로 쓰면 진도가 12주가 됩니다. 13주차(9·10장)를 삭제해 맞추세요.
- **주 2회 수업**: 각 주차를 "개념 차시 / 실습 차시"로 나누면 그대로 적용됩니다. 초급 과정에는 이 형태를 강하게 권합니다.
